**❌ 이렇게 요청하지 마세요:**
- "깃 히스토리 뒤져보라" (→ Claude Code가 git reset 할 수 있음)
- "파일 복구해줘" (→ 기본 명령어만 사용해서 못 찾을 수 있음)

**✅ 이렇게 요청하세요:**
- "git reset 하지 말고 git log로만 히스토리 확인해줘"
- "파일이 정말 없으면 Task 에이전트 사용해서 git 객체 레벨에서 찾아줘"
- "git 작업 전에 현재 상태 백업부터 해줘"

- "배포 사이트는 유지하면서 소스코드만 비공개로 하는 방법 알려줘"

**❌ 이렇게 요청하지 마세요:**

**✅ 이렇게 요청하세요:**
- "파일 삭제하지 말고 폴더로만 정리해줘"
- "중복 파일 있으면 삭제 전에 어떤 파일인지 확인부터 해줘"

## ⚠️ Claude Code 사용 시 특별 주의사항

### Git Reset 관련
- Claude Code는 "히스토리 뒤져보라"는 요청을 git reset으로 해석할 수 있음
- **해결책**: "git reset 절대 금지, git log만 사용해줘"라고 명시

### 파일 복구 능력의 한계
- 기본 git 명령어로는 unreachable 객체 못 찾음
- **해결책**: Task 에이전트 사용 요청 (고급 git 포렌식 가능)

### 배포 설정 부작용 예측 못함
- GitHub Pages와 repository 가시성 관계 모르는 경우 있음
- **해결책**: 변경 전 부작용 먼저 확인 요청

## 🛡️ 이번 사고 예방을 위한 안전 수칙

### 1. 백업 우선 원칙
```
"작업 전에 git branch backup-$(date +%Y%m%d) 만들어줘"
```

### 2. 단계별 확인 요청
```
"파일 삭제나 git reset 같은 위험한 작업은 실행 전에 먼저 알려줘"
```

### 3. 복구 작업 시 Task 에이전트 활용
```
"기본 git 명령어로 안 되면 Task 에이전트 써서 git 객체 레벨에서 찾아줘"
```

### 4. 배포 변경 시 사전 영향도 분석
```
"설정 바꾸기 전에 배포된 사이트에 어떤 영향 있는지 먼저 확인해줘"
```

## 🎯 핵심 교훈 3가지

1. **Claude Code는 "히스토리 뒤져보라"를 git reset으로 해석할 수 있다**
   → 명령어 종류를 구체적으로 제한해서 요청하기

2. **기본 git 명령어로는 reset으로 잃어버린 파일 못 찾는다**
   → 복구 작업은 Task 에이전트 필수

3. **GitHub 정책 변경사항을 미리 예측 못한다**
   → 배포 관련 변경은 사전 영향도 분석 필수
