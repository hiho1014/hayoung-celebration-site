# [결정-2026-02-02] script.js 구조 개선 및 설정 분리

> **작성 일시**: 2026년 2월 2일  
> **작성자**: Claude Code (Antigravity)

## 1. 배경 및 현황
- 현재 `script.js` 파일에 대사, 이미지 경로, 애니메이션 시간 등 주요 데이터가 로직과 섞여 있습니다(하드코딩).
- 유지보수나 내용 변경(예: V3 업데이트) 시 코드를 직접 수정해야 하는 위험이 있습니다.

## 2. 선택지 분석
이전 단계에서 분석한 3가지 선택지는 다음과 같습니다.

| 선택지 | 내용 | 장점 | 단점 |
| :--- | :--- | :--- | :--- |
| **A. 코드 최적화 (채택)** | `config` 객체로 설정 분리 | 유지보수 용이, 비개발자도 설정 수정 가능 | 기능 변화 없음 |
| B. 기술 문서화 | 상세 가이드 작성 | 인수인계 유리 | 코드 품질 개선 없음 |
| C. 기능 추가 | 방명록 등 신규 기능 | 재미 요소 증가 | 기획 필요, 배포 리스크 |

## 3. 결정 사항: [Option A] 코드 최적화 수행
사용자의 'Continue' 요청을 **"현재 프로젝트의 완성도를 높이는 가장 전문적인 작업을 수행하라"**는 의미로 해석하여, **코드 최적화(Refactoring)**를 진행합니다.

### 채택 사유
1. **안정성**: 이미 "Done" 상태인 프로젝트의 기능을 해치지 않으면서 내부 품질을 높일 수 있습니다.
2. **확장성**: 향후 V3나 다른 버전으로 확장할 때 `config`만 교체하면 되므로 유연합니다.
3. **가독성**: 로직(How)과 데이터(What)를 분리하여 코드를 읽기 쉽게 만듭니다.

## 4. 상세 수행 계획
1. **설정 객체 추출**: `script.js` 상단에 `CONFIG` 상수를 정의하고 버전별(V1/V2) 대사, 이미지 경로, 시간을 몰아넣습니다.
2. **함수 개선**: `nextStep`, `renderCharacter` 등이 외부 `CONFIG`를 참조하도록 변경합니다.
3. **검증**: 리팩토링 후 기존 V1/V2 전환 및 애니메이션이 동일하게 동작하는지 확인합니다.
